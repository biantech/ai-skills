# 最小化查询规划

只获取足以回答调查问题的最少运行时证据，不要把返回条数限制误认为扫描成本限制。

本文档与 [SKILL.md](SKILL.md) 对应。修改任一版本时，应保持两者行为一致。

## 明确查询边界

查询前确定：

- 待验证的假设，以及能够确认或否定它的观察结果；
- 权威数据源；
- 明确的环境、集群、数据库、索引、数据表或键命名空间；
- 已批准的查询方式和可用的只读凭据。

不要根据 `dev`、`local` 或 `prod` 等名称自行推断环境。遵循工作区指令和用户提供的映射。如果目标仍有歧义，且查询错误系统会产生实质影响，应在执行前询问。

只有当用户请求和工作区策略明确将相应数据源纳入范围时，才可以查询实时数据。本 Skill 不授权访问生产环境、提升权限，也不授权使用从文件中发现的凭据。

## 按成本规划，而不只看输出量

在相关时按以下顺序推进：

1. 检查已有代码、结构定义、映射或键结构文档。
2. 检查选择高选择性访问路径所需的轻量元数据。
3. 执行点查或过滤条件高度精确的有界查询。
4. 只有当前一步结果不足时，才逐次扩大一个范围维度。

评估操作中真正昂贵的部分：检查的行或文档数量、遍历的键、涉及的分片、加载的字段、聚合桶、排序，以及锁和超时风险。`LIMIT`、Elasticsearch `size` 和 Redis `SCAN COUNT` 只能限制返回批次或提供提示，不能保证服务端工作量有界。

两个查询返回相同行数时，优先选择执行计划成本更低的查询。当执行计划不确定时，可使用不会实际执行查询的 explain 功能。除非已经理解执行成本且明确在任务范围内，否则不要使用会执行查询的 `EXPLAIN ANALYZE` 或同类功能。

## 只读安全

只使用已知在目标系统中确实只读的操作。不要运行：

- 插入、更新、删除、DDL、修复、缓存失效、重建索引或管理变更；
- `FOR UPDATE`、显式锁或长事务等锁定式读取；
- 可能产生副作用的存储过程、自定义函数、脚本或命令；
- 大范围导出，或读取无关的密码、凭据、令牌和个人数据。

系统支持时设置服务端超时或取消限制。只选择验证假设所需的字段，在报告中脱敏敏感值，绝不把凭据写入查询记录。

## 各数据源指导

### SQL 数据库

- 优先使用索引列上的等值或窄范围条件、已知主键，或高选择性联合索引前缀。
- 当过滤选择性或索引使用不确定时，检查访问计划。
- 明确选择字段；结果顺序有意义时添加确定性排序。
- 使用较小的 `LIMIT`，但如果执行计划仍扫描不可接受的大范围数据，应拒绝该方案。
- 分页优先使用键集条件，避免较大的 `OFFSET`。
- 避免前导通配符、在索引过滤列上使用函数或类型转换、无界连接，以及对大范围数据做无必要的精确计数。

### Redis 及类似键值系统

- 优先使用精确键。选择读取命令前检查键类型，仅在相关时检查 TTL 或内存大小。
- 不要在实时共享实例上使用 `KEYS`。
- 只有在模式足够窄且客户端设有停止条件时才使用增量 `SCAN`，并将 `COUNT` 视为提示而非硬限制。
- 限制集合读取范围。在确认大小并说明必要性之前，避免可能很大的 `HGETALL`、`SMEMBERS`、`LRANGE 0 -1` 或同类整值读取。

### Elasticsearch 及类似搜索系统

- 指定最窄的索引或别名，并在映射支持时使用精确 term 或 range 过滤。
- 只请求必要字段，设置较小的 `size`，并在支持时设置超时。
- 如果精确总数不是调查所需证据，应关闭或限制精确命中总数计算。
- 没有成本说明时，避免宽泛通配符、正则、脚本、深分页、不受限的多索引搜索和高基数聚合。
- 在选择 `term`、全文搜索、排序或聚合字段前检查映射。

对于其他系统，沿用同一模型：识别其工作量单位，选择高选择性访问路径，限制返回数据，并在可用时增加执行保护。

## 逐步扩大范围

查询结果不足时：

1. 说明仍缺少什么证据。
2. 每次只改变一个范围维度，例如时间范围、标识符集合、字段、索引或样本量。
3. 说明扩大后的查询为什么能够消除当前歧义。
4. 证据充分或下一次查询成本不成比例时停止。

除非瞬时行为使重试具有明确意义，否则不要原样重复昂贵查询。

## 结果报告

报告详细程度应与调查相匹配。对于每个有实质意义的查询，保留足以复现和评估的信息：

- 目标和环境，但不包含秘密；
- 假设；
- 精确的只读查询或命令；
- 成本控制和相关执行计划观察；
- 结果摘要和结论：`confirmed`、`rejected` 或 `inconclusive`；
- 仅在确有需要时给出下一条最小查询。

使用当前工作区强制指定的查询工具。否则优先使用项目已有辅助工具或专用连接器，不要临时开发新客户端。可复用指令中不得硬编码机器专属路径。
