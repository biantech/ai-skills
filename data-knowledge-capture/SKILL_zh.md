# 数据知识沉淀

支持两种独立操作：只读发现相关历史知识，以及经过明确授权后持久化可复用知识。调用本 Skill 不代表授权访问无关的数据系统、重新执行已沉淀的操作，也不代表用户已经授权写入知识库；只有用户明确要求保存或更新时才能写入。

## 确定知识库位置

使用用户指定或当前工作区已经约定的知识库路径。当前安装的候选路径是 `/Users/bianjq/data/data-knowledge`，但该目录可能不存在，也不能假设其他环境具有相同路径。

- 执行发现时，如果确定的目录不存在，简洁说明后停止。不得为了搜索而顺带创建目录。
- 执行持久化时，仅要求分析、审查或总结只授权在对话中输出总结。只有用户明确要求保存、沉淀、持久化或更新可复用知识时才能写文件。
- 用户要求持久化但尚未约定知识库时，在当前工作区之外创建目录前先确认目标位置。
- 修改已有任务目录前先检查其内容。保留无关内容和人工维护内容，只更新相关文件，遇到同名冲突时不得静默覆盖。

## 查找历史知识

仅当当前请求确实需要复用历史知识时搜索。先使用业务对象、来源系统、转换步骤和输出的聚焦关键词搜索文件名与内容；只读取最相关的 `summary.md`、`.sql` 或 `.py` 文件，不得一次加载整个知识库。

历史材料只是线索，不代表当前事实。复用前验证环境、Schema、字段、依赖、假设和安全性。报告复用了哪个文件以及做了哪些调整。没有相关内容时正常继续，不创建占位文件。

## 判断留存价值

只有材料至少保留以下一种价值，且能够显著减少未来工作时才持久化：

- 可重复的导入、导出、清洗、匹配、映射或验证模式；
- 输入输出稳定且已参数化的 SQL 或脚本；
- 已验证的 Schema 关系、业务规则、数据流或执行顺序；
- 预览、验证、幂等、回滚或运行安全措施；
- 可支持具体平台能力的重复人工决策。

以下内容不应持久化：仅用于一次任务的固定 ID 或值列表、可由上游材料重新生成的输出、原始执行证据，以及不含复用逻辑的过程叙述。用户明确要求持久化但最终决定跳过时，应说明原因。

## 持久化前脱敏

只留存知识，不留存实时数据。写入或复制任何文件前：

- 删除凭据、令牌、Cookie、私钥、连接字符串、签名 URL 和包含秘密的命令；
- 排除原始数据库记录、生产导出、日志、查询结果转储及个人或机密数据，示例使用合成值或脱敏值；
- 在不破坏模式的前提下，将环境相关 ID、路径、日期、主机、索引和目标表改为有说明的参数；
- 检查脚本中的内嵌秘密、隐式破坏性默认值、网络访问和外部副作用；
- 不得把生产变更 SQL 原样保存成可直接执行的命令。应将其参数化、默认标记为不安全，并在已知时说明预览、验证、幂等和回滚要求；
- 未知内容继续标记为未知，不得编造执行结果、Schema、平台需求或回滚保证。

只有知识库副本本身具有复用价值时，才复制或提取脚本。记录原始来源路径，并在可用时记录版本或采集日期。不得复制临时脚本、依赖、原始输入、生成输出或表达相同逻辑的重复材料。

## 文件布局

每项任务使用一个简短的小写 slug，并保持目录精简：

```text
<knowledge-root>/<task-slug>/
|-- summary.md
|-- reusable_script.py   # 仅在确有价值时创建
`-- reusable_query.sql   # 仅在确有价值时创建
```

不得创建占位文件。优先保留 `summary.md` 和最小数量的核心材料。

总结只包含适用章节：

```markdown
# 任务名称

## 用途与复用条件
## 范围、来源与假设
## 输入、Schema 与可编辑参数
## 数据流与业务规则
## 可复用脚本或 SQL
## 使用与适配方法
## 验证与预期输出
## 风险、幂等与回滚
## 平台能力机会
```

平台能力机会只是基于重复人工工作的假设，不是已批准的架构。任务没有可信信号时省略该章节。

## 完成沉淀

将保存的总结和复用材料与已完成任务进行核对。安全且有意义时运行本地语法检查或 dry-run 验证，但不得仅为验证沉淀结果而重新连接服务或重复外部操作。最后报告知识库路径、新建或更新的文件、执行过的脱敏或泛化、完成的验证以及剩余假设。
