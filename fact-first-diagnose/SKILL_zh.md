# 事实优先诊断

以证据构建诊断，并清楚呈现证据边界。诊断请求授权为定位原因所需的只读检查，但不会自动授权修改代码或数据、清理缓存、重启服务、修改配置或执行其他修复操作。

## 判断主张类型

仅当现有代码、规范、数学推导、编译器输出或聚焦测试无需假设实时状态即可证明某个主张时，才将其视为逻辑可证。常见情况包括语法和类型错误、无条件空指针访问、确定性的边界错误或违反已有 API 规范。测试只能支持它实际覆盖的行为与输入。

如果某个主张在代码不变时仍可能随运行状态改变，则属于数据依赖。常见情况包括：

- 某条记录是否存在或是否具有特定值；
- 生效配置、功能开关、路由或实际部署版本；
- 缓存内容、过期时间、命中状态或与事实源的一致性；
- 搜索索引内容或同步延迟；
- 排序结果、数据分布、流量规模或实际延迟；
- 外部依赖的状态和时序。

不得根据代码默认值、迁移文件、fixture、快照或预期配置推断实时状态。反过来，单个运行时观测也不能证明由哪条代码路径导致；确认因果关系前，应将观测结果与相关逻辑连接起来。

## 调查流程

1. 明确实际表现、预期表现、环境、时间窗口、相关标识符和近期变更。不得静默替换为其他环境。
2. 跟踪最小相关代码路径，记录它能够证明的内容，并找出所有仍依赖运行状态的假设。
3. 将主要假设改写为可证伪的假说，选择能够区分它们且侵入性最低的证据。
4. 仅在确有必要、工具可用且目标处于用户授权范围内时检查实时状态。先检查元数据或健康状态，再执行有界样本或聚合，最后执行一项聚焦验证，避免宽泛扫描。
5. 当证据足以按所声明的置信度支持原因时停止。证据不可用或互相冲突时，报告未解决的假设和最小下一步检查，不得伪装成确定结论。

优先使用现有日志、链路追踪、指标和只读查询。跨系统关联时保留原始时区，并报告转换后的时间边界。命令和结果中应隐藏凭据、令牌、个人数据及无关的负载字段。

## 运行时证据路由

- 对 Redis、Elasticsearch、配置中心、日志、链路追踪或指标，仅在存在对应的只读工具，且目标系统和环境已纳入范围时使用该工具。`$db-tools` 不能作为这些系统的证据。
